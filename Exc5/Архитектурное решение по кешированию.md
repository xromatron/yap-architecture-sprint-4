# Какую часть системы имеет смысл закешировать

## Internet Shop - Shop API

1. Кеширование на стороне клиента

- статические элементы для создания 3D-моделей

2. Кэширование на стороне сервера

- список готовых вариантов изделий (меняются редко, нет смысла при каждом обращении клиента ходить в БД)

## MES - MES API

2. Кэширование на стороне сервера

- список заказов в работе
- инвалидация кэша при поступлении нового заказа и изменении статуса

# Мотивация

Кэширование на стороне клиента статических элементов сайта, которые редко меняются, позволят клиентам
меньше ждать загрузки сайта и оперативнее работать в 3D-конструкторе.
Время жизни кеша можно поставить исходя из того, как часто добавляются новые модели.

Кеширование на стороне сервера списка готовых вариантов изделий позволит не обращаться при каждом вызове
клиента в БД, что ускорит время отклика и скорость работы клиента с сайтом.

Кеширование списка заказов на стороне сервера позволит отдавать информацию, которую запрашивает много операторов,
и которая не зависит от того что запрашивает, гораздо быстрее без обращения в БД.
Для поддержания консистентности данных необходимо настроить инвалидацию кеша при изменении статуса заказа.
Cash-Aside не подходит, т.к. обрабатываются только операции чтения, запись проходит мимо -> 
несогласованность данных
В случае со списком заказов необходима самая свежая информация, чтобы несколько операторов не могли взять
один и тот же заказ.

# Предлагаемое решение

## Shop API

В части получение списка готовых вариантов изделий применить кеширование на стороне сервера
Refresh-Ahead
Инвалидация кэша по времени - например раз в сутки (в зависимости от частоты добавления новых вариантов)

# MES API

В части получения списка заказов в работе
Будем использовать: Cash-Aside - позволяет кэшировать не все записи в базе, а конкретную выборку, 
например новые заказы, заказы в работе, ... Именно то, что актуально для операторов.
Необходимо использовать стратегию инвалидации (программную)
Почему не:
Read-Through - ограничения не выбор модели данных в кэше
Refresh-Ahead - Срок истечение - не установлен, обновлять кеш без необходимости не нужно

Кеш Write-Through и Write-Behind не используем, т.к. запись будет по конкретному заказу, 
а кэш нужен в виде списка + требуется программная инвалидация кэша при записи
