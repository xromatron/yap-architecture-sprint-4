# Из каких систем требуется сбор логов, какие логи нужно собирать
Shop API:
1. Взаимодействие с Internet Shop
- запрос/ответ на оформление заказа
- загрузка 3d модели
- оплата заказа
2. Взаимодействие с Shop Db
- запись в БД
- результат записи в БД
- чтение из БД
3. Взаимодействие с 3d files storage
- загрузка файла
- результат загрузки

CRM API:
1. Взаимодействие с CRM
- запрос/ответ на список заказов
- запрос на подтверждение заказа
- запрос на закрытие заказа как выполненного
2. Взаимодействие с Shop Db
- чтение из БД
3. Взаимодействие с 3d files storage
- запрос/ответ информации о загруженном файле для заказа
4. Взаимодействие с RabbitMQ
- отправка событий

RabbitMQ:
- поступление сообщений
- отправка сообщений

MES API:
1. Взаимодействие с MES
- запрос/ответ на список заказов
- запрос на подтверждение взятие заказа в работу
- запрос на изменение статуса заказа как изготовленного
- запрос на изменение статуса заказа как доставленного/выполненного
2. Взаимодействие с MES Db
- запись в БД
- результат записи в БД
- чтение из БД
3. Взаимодействие с 3d files storage
- выгрузка 3d модели
4. Взаимодействие с RabbitMQ
- отправка событий
5. Взаимодействие с API USer
- аналогично MES

При ошибках запросов уровень логирования ERROR

При ошибках аутентификации уровень логирования WARN

# Обязательные поля:
- время
- идентификатор покупателя
- номер заказа
- идентификатор менеджера/оператора
- сумма (для операций оплаты)
- размер (для операций с файлами моделей)

# Мотивация
Логирование позволяет посмотреть:
- кто, когда и с какими параметрами делал запросы
- результаты запросов
- отследить были ли ошибки по запросам и по каким заказам/клиентам
Это дает возможность быстрее провести расследование, если с каким-то заказом что-то пошло не так. 
Сокращает время DevOps на разбор инцидентов.
В конечном итоге повышает удовлетворенность пользователей за счет оперативного решения их вопросов.
Логирование необходимо на всех "границах" сервисов, чтобы фиксировать как входящие,
так и исходящие запросы и их результаты.

## Политика безопасности
К логам на ПРОМ имеет доступ только пользователи с ролью "Поддержка"

## Политика хранения в отношении логов
Используем Hot-Warm-Cold хранение
Hot: неделя
Warm: месяц
Cold: Три месяца (макс срок выполнения заказа - 2 месяца)

# Превращение системы сбора логов в систему анализа логов
Не требуется, алертинг должен быть настроен в мониторинге
