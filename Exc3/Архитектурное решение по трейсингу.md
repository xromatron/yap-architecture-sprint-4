# Где заказ может "сломаться" или "зависнуть":
Shop API:
- не удалось загрузить файл в 3d file storage - сразу ошибка передается в Internet Shop
- не удалось записать данные в Shop Db - сразу ошибка передается в Internet Shop
* нет необходимости в tracing

CRM API:
- проблема при вычитывании данные из Shop Db о новых заказах - сразу ошибка в CRM
- проблема при вычитывании файлов из 3d file storage - сразу ошибка в CRM
* нет необходимости в tracing

- отправка информации о новых заказах - может не дойти до MES API
- получение статуса изменения заказов - может не дойти до CRM API
* нужен tracing

MES API:
- не удалось загрузить файл из 3d file storage - сразу ошибка передается в MES
- не удалось записать данные в MES Db - сразу ошибка передается в MES
* нет необходимости в tracing

- получение информации о новых заказах - может не дойти до MES API
- отправка статуса изменения заказов - может не дойти до CRM API
* нужен tracing

Нам нужно убедиться, что все события о заказе доходят до получателей
Т.е. tracing нужно внедрить в CRM API, MES API, RabbitMQ

# Данные, которые должны попасть в tracing
- id заказа
- id клиента
- время отправки/получения события
- микросервис
- эндпоинт
- топик
- событие

# Мотивация
Внедрение трэйсинга позволит:
1. оперативно выявлять узкие места, причины медленной работы сервисов
2. определить приоритеты где именно доработать, масштабировать, кэшировать
3. сократит время на поиск потерявшихся заказов и разбор инцидентов
4. в итоге это приведет к сокращению количества недовольных клиентов и росту доходов
