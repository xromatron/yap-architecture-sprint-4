# Мотивация

В настоящее время у нас нет понимания причин возникновения проблем, на которые жалуются пользователи
нашей системы. Мы не видим узкие места, не понимаем где необходимо внести изменения.

Необходимо добавить в систему мониторинг. Это позволит
1. Получить представление о работе системы, количество запросов, загруженность системы, ошибки.
2. Понять где необходимо масштабироваться, где изменить логику или применяемый инструмент.
3. Проверять влияние изменений в программе
4. Оперативно реагировать на сбойные ситуации.
5. В итоге это приведет к сокращению количества потерянных заказов, повышению удовлетворенности 
   пользователей и росту их количества, а значит - к росту доходов.

# Метрики, которые необходимо добавить
1. Общие метрики для всех:
   - % использования CPU, RAM для отслеживания необходимости масштабирования
   * метки имени каждого контейнера
2. Для всех БД:
   - % использования HDD для отслеживания необходимости масштабирования
   * метки имени каждой реплики
3. Для всех API:
   - RPS - количество запросов - сбор аналитики роста 
   - MES: RPS per user - количество запросов на пользователя - выявление проблем с повторными запросами пользователя 
   - длительность запросов - выявление проблемных запросов
   - количество успешных ответов - выявление проблемных запросов 
   - количество ошибок - выявление проблемных запросов
   - входящий трафик - анализ объема данных для планирования увеличение БД
   - исходящий трафик - анализ объема данных для планирования увеличение БД
   * необходимо добавить метки id пользователя для выявления аномалий конкретных пользователей
4. Для очереди:
   - количество producers - выявление "отвалившихся"
   - количество consumers - выявление "отвалившихся"
   - количество успешно доставленных сообщений - анализ общего объема сообщений
   - количество сообщений не получивших ack - выявление проблем
   - количество сообщений в очереди - выявление пиковых нагрузок
   * для сообщений добавить метки - имя события, чтобы понимать с какими именно событиями проблемы
